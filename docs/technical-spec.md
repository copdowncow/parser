# Техническое задание: AI Job Opportunity Radar

## 1. Общая информация

### 1.1 Название
AI Job Opportunity Radar

### 1.2 Тип системы
SaaS-платформа (веб-сервис) для разработчиков, которая автоматически находит задачи по программированию,
анализирует их с помощью ИИ и определяет проекты с высокой вероятностью получения заказа.

### 1.3 Цель
Построить платформу, которая:
- мониторит интернет-источники с задачами по программированию;
- анализирует текст задач;
- оценивает уровень конкуренции;
- определяет вероятность получения заказа;
- уведомляет пользователя о лучших возможностях.

---

## 2. Основные задачи
1. Автоматический сбор задач из открытых источников.
2. AI-анализ задач.
3. Оценка уровня конкуренции.
4. Расчёт Opportunity Score (0–100).
5. Уведомление пользователя в реальном времени.
6. Dashboard с аналитикой.

---

## 3. Целевая аудитория
- фриланс-разработчики;
- аутсорс-студии;
- стартап-команды;
- IT-специалисты, ищущие проекты.

---

## 4. Источники данных (только публичные)
- публичные job boards;
- GitHub Issues с метками `help wanted`;
- форумы разработчиков;
- публичные сайты вакансий;
- открытые каналы вакансий (без обхода авторизации).

> Сбор данных выполняется только с легально доступных публичных страниц.

---

## 5. Функциональные требования

### 5.1 Модуль парсинга задач
Система должна:
- сканировать источники каждые `N` минут;
- извлекать новые задачи;
- исключать дубликаты;
- сохранять задачи в БД.

Поля задачи:
- `title`;
- `description`;
- `source`;
- `url`;
- `technologies`;
- `budget` (если указан);
- `published_at`.

### 5.2 AI-анализ
Для каждой задачи:
- извлечение технологий (React, Node, Python и т.д.);
- определение типа проекта (frontend/backend/fullstack/mobile/AI);
- оценка сложности;
- оценка срочности;
- оценка релевантности навыкам пользователя.

### 5.3 Оценка конкуренции
Классы конкуренции:
- низкая;
- средняя;
- высокая.

Сигналы:
- время публикации;
- активность обсуждения;
- тип заказчика;
- бюджет.

### 5.4 Opportunity Score (0–100)
Предлагаемая базовая формула:

`score = 0.30*freshness + 0.30*skills_match + 0.20*competition_inverse + 0.10*budget_score + 0.10*urgency_score`

Где каждая составляющая нормализована в диапазоне 0–100.

- `freshness`: чем свежее задача, тем выше балл;
- `skills_match`: совпадение с профилем пользователя;
- `competition_inverse`: низкая конкуренция = высокий балл;
- `budget_score`: достаточность бюджета для пользователя;
- `urgency_score`: умеренная/высокая срочность (как сигнал быстрого найма).

### 5.5 Фильтры
Пользовательские фильтры:
- технологии;
- минимальный бюджет;
- тип задач;
- язык проекта;
- уровень сложности;
- уровень конкуренции.

### 5.6 Уведомления
Триггеры:
- появилась новая задача;
- `Opportunity Score` выше порога;
- задача релевантна навыкам пользователя.

Каналы:
- Telegram;
- Email;
- Web push (перспектива).

### 5.7 Dashboard
Отображает:
- список задач;
- Opportunity Score;
- уровень конкуренции;
- стек технологий;
- фильтры и поиск;
- агрегированную статистику.

### 5.8 Генерация откликов
AI генерирует отклик заказчику:
- краткий;
- релевантный стеку;
- профессиональный.

---

## 6. Нефункциональные требования

### 6.1 Производительность
- обработка одной задачи: не более 2 секунд;
- поддержка тысяч задач в сутки.

### 6.2 Масштабируемость
- добавление новых источников без изменения ядра;
- горизонтальное масштабирование парсеров.

### 6.3 Надёжность
- автоматический повтор при ошибках;
- очереди задач для устойчивости.

### 6.4 Безопасность
- хранение только публичных данных;
- защита API-ключей;
- шифрование конфиденциальных настроек.

---

## 7. Архитектура

`Parsers -> PostgreSQL -> AI Analysis -> Scoring Engine -> API -> Dashboard/Notifications`

Поддерживающие компоненты:
- `Redis + BullMQ` для фоновых очередей;
- scheduler для периодического запуска парсеров;
- observability слой (логи, метрики, алерты).

## 10. Алгоритм работы
1. Планировщик запускает парсеры.
2. Новые задачи нормализуются и сохраняются в БД.
3. AI-модуль анализирует описание.
4. Scoring Engine считает Opportunity Score.
5. Применяются пользовательские фильтры.
6. Notification Service отправляет алерты.
7. Dashboard показывает ленту и аналитику.

---

## 13. Definition of Done (MVP)
MVP считается завершённым, если:
1. система парсит минимум 1 публичный источник по расписанию;
2. сохраняет задачи без дубликатов;
3. рассчитывает Opportunity Score;
4. отправляет Telegram-уведомления по порогу;
5. предоставляет API для получения списка задач с фильтрами.
